# A3: O TTL que não apaga

## Diagnóstico (mongo/A3.out.txt)
- Índice existente: { registrado_em: 1 } com expireAfterSeconds: 2592000 (30 dias).
- db.alertas.countDocuments() = 100.000, nada foi removido.
- Comando de prova:
  db.alertas.aggregate([{ $group: { _id: { $type: "$registrado_em" }, n: { $sum: 1 } } }])
  Resultado: [ { _id: 'string', n: 100000 } ]
- Exemplo de documento: registrado_em: '2026-02-05T01:17:26.089Z' (texto).

## Causa raiz
O índice TTL só expira documentos cujo campo indexado é do tipo BSON Date (ou um
array de valores Date). O monitor de TTL do MongoDB roda a cada 60 segundos e
compara o valor do campo com a hora atual; documentos em que o campo não é Date
são ignorados, sem erro e sem aviso. Aqui todos os 100.000 documentos gravaram
`registrado_em` como string ISO (toISOString()), então nenhum é elegível.
O índice em si está correto; o defeito está no tipo do dado gravado.

## Comando de índice correto
db.alertas.createIndex({ registrado_em: 1 }, { expireAfterSeconds: 2592000 })
(30 dias = 30 x 24 x 60 x 60 = 2.592.000 s). O índice precisa ser de campo único.

## Como a aplicação deve gravar os novos alertas
Gravar `registrado_em` como Date, não como string:
  db.alertas.insertOne({ sensor: "S1", nivel: "info", registrado_em: new Date() })
No driver, enviar um objeto Date do próprio idioma (por exemplo, `new Date()` em
JavaScript), nunca `new Date().toISOString()`. Os documentos antigos em string
não precisam ser migrados (conforme o enunciado) e continuarão sem expirar.
